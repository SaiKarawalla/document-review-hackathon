# Local review boundary

Latest target: native iPhone interface in Expo Go (`mobile/`). Real bundled/user-selected PDF bytes are read into phone memory and parsed by PDF.js in a disposable WKWebView with no remote assets/connections. WKWebView's missing ReadableStream async iterator is shimmed inside this engine. Cancelling/remounting disposes the engine; parsing has a 15-second bound. The Files picker app-cache copy is deleted after reading even on validation failure; user originals remain. Shared TypeScript comparison/minimization rules run on the phone. Source pages render to canvas in a second local WebView. No phone-local model inference.

Phone-to-Mac: private QR supplies a random temporary AES-256-GCM key and a strict private-IP endpoint. Correlated, timestamped encrypted requests carry only allowlisted gateway commands and minimized facts. The separate companion binds a single private IP on 8790, checks Host/no browser Origin, body/rate/concurrency limits, replay/expiry and preview ownership. It proxies fixed loopback API routes to the existing single gateway below; it does not create a second model queue or accept document uploads. The phone verifies preview hash and response receipt/schema. Health/preview requests have eight-second client timeouts; generation has 70 seconds. Reset/correction cancel and invalidate; background also clears pairing.

This development LAN transport uses HTTP with encrypted application payloads, not TLS; connection metadata and Expo's development bundle delivery are outside that envelope. Private pairing QR possession permits access during its lifetime. No public tunnel, provider key, paid build or cloud deployment. Compromised endpoints/development network/OS captures remain limitations. Physical-iPhone Camera/Files and venue connectivity need their own rehearsal. The web baseline remains available below; its browser receipts do not prove native behavior.

This deliberately limits generative freedom. Tests with controlled provider responses are clearly test doubles, separate from real model integration checks.

## Phase 6 — current Expo Go architecture

ExpoGo iPhone → phone-local PDF.js in disposable network-disabled WebView → shared selected-layout extraction / deterministic review → financial-purpose evidence decisions and confirmation → strict context schema → AES-256-GCM private companion → existing loopback gateway → cloud-disabled local Ollama qwen2.5:1.5b on Mac. Documents and literal source values never cross this API. The encrypted LAN transport is not TLS; trust the development network and delivered Expo bundle. Mac must stay running.

`visa.ts` checks selected official-reference geometry/anchors and reads eight typed records; `workflow.ts` runs one-/two-document checks and a fixed fictional financial policy. `request.ts` preserves original baseline schema and adds bounded visa/purpose schema. `ModelGateway` still builds/stores exact serialized provider bytes and sends those stored bytes after hash approval; dynamic allowed response schema covers only the supplied findings. Output sentence vocabulary/semantic validation remains authoritative. No external tool capability.

`locales.ts` provides EN/ES/HI/zh-Hans/FR display dictionaries. Only UI and canonical validated model sentences use display translation; values, filenames, excerpts, raw PDF canvases and exact body/hash/receipt use raw rendering. Language switching is display-only and creates no request; correction/purpose changes invalidate/cancel. Canonical model output is real English constrained Qwen output, with translated-display disclosure. Native standalone source retained separately, not imported by ExpoGo’s entry screen.

Proof counters measure supported field records including absent slots, local selection/exclusion, derived finding count in actual context. They are not raw-form field counts, a privacy percentage, or a claim that prepared data has already been sent. Fixed sample policy/confirmation/statuses do not establish legal eligibility, authenticity or account ownership.
